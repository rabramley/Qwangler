# Qwangler AI Development Guide

This document provides instructions for using AI agents to develop, maintain, and extend the [Qwangler](https://github.com/rabramley/Qwanger) Python TUI music queue manager project.

---

## 📋 Project Overview

**Qwangler** is a Python-based TUI music queue manager that supports:
- Playlist management with multiple playlists
- Media tree browsing (local files, directories, network)
- Cross-platform UI using `curses`/`bat`
- A modular architecture separating CLI, app logic, and data layers

---

## 🛠️ Development Setup

### Install the project locally
```bash
uv pip install -e ".[dev]"
```

This installs:
- The core Qwangler library
- `pytest` for testing
- `ruff` for linting and formatting
- `ty` for type checking
- Pre-commit hooks

Note: All commands below use `uv run <command>` to ensure you're using the project's isolated environment with the correct dependencies.

### Configure pre-commit hooks (recommended)
```bash
uv pip install pre-commit
uv run pre-commit install
```

This ensures every commit passes linter/format checks automatically.

## 🤖 AI Agent Workflows

Use the following patterns when working with an AI agent on this project:

### 1. New Feature Development

**When you want to add a new feature:**

1. **Define the scope clearly**:
   > "I want to add support for [feature]. It should:
   > - Accept user input via CLI
   > - Store data in SQLite/JSON
   > - Have unit tests with edge cases"

2. **AI will**:
   - Suggest a file structure and module breakdown
   - Implement the feature incrementally
   - Write tests alongside implementation
   - Add type hints and docstrings

3. **Follow up**:
   > "Run `uv run ruff check .` and `uv run python -m pytest` to verify everything passes"

### 2. Debugging & Bug Fixes

**When you encounter an error:**

1. **Share the full output**:
   > Paste the traceback, test failure output, or any relevant logs. Include:
   > - The command that triggered it
   > - Any environment context (OS, Python version, dependencies)

3. AI will:**
   - Analyze the error message and identify the root cause
   - Explain why it happens
   - Propose a fix with reasoning
   - Suggest related tests to add or update

3. **Verify**:
   > "Run `uv run python -m pytest` to confirm the test passes"

### 3. Refactoring & Code Improvement

**When you want to improve existing code:**

1. **Be specific about what you want**:
   > "Refactor the media parsing logic into its own module. The goal is to:
   > - Separate concerns (parsing vs. data models)
   > - Make it testable independently
   > - Keep behavior identical"

2. **AI will**:
   - Suggest a refactoring plan
   - Implement the changes incrementally
   - Run diagnostics to check for regressions
   - Add missing type hints and docstrings

3. **Verify**:
   > "Run `uv run python -m pytest` — all tests should still pass"

### 4. Code Review & Learning

**When you want to understand or improve existing code:**

1. **Request explanations**:
   > "Explain how the media tree data structure works and why it's designed this way."

2. **Request improvements**:
   > "Review `cli.py` for:
   > - Potential performance bottlenecks
   > - Missing error handling
   > - Opportunities to improve testability"

3. AI will provide analysis with specific line references** and actionable suggestions.

## ✅ Best Practices for AI Collaboration

| Practice | Why It Helps |
|----------|-------------|
| **Write failing tests first** | Gives AI a clear specification of expected behavior |
| **Use descriptive function names** | Makes intent obvious to both humans and AI |
| **Add docstrings to public APIs** | Documents contracts between modules |
| **Keep modules focused** | One module = one responsibility; easier for AI to reason about |
| **Run `ruff check .` before AI edits** | Establishes a clean baseline for comparison |
| **Verify after each major change** | Prevents compound bugs from accumulating |

## 🧪 Testing & Validation Commands

```bash
# Run all tests with verbose output
uv run python -m pytest -v --tb=short

# Run tests in watch mode (for interactive development)
uv run python -m pytest -w

# Check for linting/formatting issues
uv run ruff check .
uv run ruff format --check .

# Type check the codebase
ty --recursive .

# Quick sanity check script (run before commits)
uv run python run_checks.py
```

## 💡 Tips for Effective AI Collaboration

### Do:
- ✅ Be specific about requirements and constraints
- ✅ Share error messages and test outputs in full
- ✅ Request incremental changes rather than massive refactors
- ✅ Ask the AI to explain its reasoning for non-obvious decisions
- ✅ Validate each major change before proceeding

### Don't:
- ❌ Expect the AI to know context from previous conversations (each session is independent)
- ❌ Use vague requests like "fix this" without specifying what's wrong
- ❌ Ask for changes that would require understanding unrelated code
- ❌ Trust output blindly — always verify with tests

## 🔄 Example Workflow: Adding a New Feature

**Task:** Add support for creating playlists from scratch via CLI.

```
Step 1: Define the feature
> "I want to add CLI commands for creating, listing, and deleting playlists."

Step 2: AI proposes plan
> Suggests adding `create_playlist`, `list_playlists`, `delete_playlist` 
> to cli.py with corresponding data layer functions.

Step 3: Implement incrementally
> 1. Add data layer (playlist CRUD operations)
> 2. Add CLI commands
> 3. Write tests for each piece
> 4. Run ruff check + pytest

Step 4: Verify
> python -m run_checks.py && python -m pytest -v
```
